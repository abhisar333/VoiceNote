VoiceNote — Technical Spec Visual companion to the blueprint: architecture, the voice round-trip, and every component traced to the PRD it implements.

The whole machine: one screen, one note.json on the phone, and one round-trip to a free Whisper model on Hugging Face that returns your words with the time each was spoken — which is what makes word-precise replay possible. Everything else is local.

How It Runs

Primary: Expo Go (zero build)

npm install → npx expo start → scan QR with Expo Go. Mic permission prompt on first record. Internet only for transcription.

Fallback: local build

If Expo Go blocks anything: npx expo run:android — compiles locally with the Android SDK, no EAS account, no cloud queue. (Approved in scope.)

Architecture

The Voice Round-Trip

1

Tap the red button → recorder.start() captures the mic; the button pulses while it hears sound. prd.md › Capture

2

Tap again → recording stops; the file is moved to documents/recordings/ permanently.

3

A voice segment (words: null) joins the note → bubble shows the 1-2-3 dots → note.json saved.

4

transcri.ts uploads the file to Hugging Face Whisper → back comes the text with a timestamp per word.

5

Text fills the bubble; words stored. Silent take → empty result → no segment + "no audio recorded". prd.md › Transcription

6

View mode: long-press a word → vibrate → player seeks to word.startMs → ring animates top-left → release stops. prd.md › Replay in place

7

Edit mode: tap a bubble's text to fix it, tap empty space to type a new segment → save. prd.md › Modes

8

Force-quit & reopen → noteStore.loadNote() restores segments, text, order, audio. prd.md › States & Edge Cases

Components → PRD Behaviors

SegmentBubble · ProgressRing · RecordButton · ModeToggle
  • SegmentBubble — typed text vs grey translucent voice bubble; the 1-2-3 dots while words: null; per-word spans for long-press; inline text editing; "transcription unavailable" state (audio kept, replay works). prd.md › Replay in place, Modes, States & Edge Cases
  • ProgressRing — circular ring, top-left, 0→100% from ~10 Hz position ticks during playback. prd.md › Replay in place
  • RecordButton — round red, bottom right, tap start / tap stop; pulses on live mic level, fallback: continuous pulse while recording. prd.md › Capture
  • ModeToggle — fixed top-right; edit is default on open (empty note shows its cursor). prd.md › Modes
recorder · player · noteStore · transcri (+ segments pure logic)
  • recorder — expo-audio start/stop, temp file → permanent storage (DESIGN.md 3.3 kept), exposes mic level.
  • player — load, seekTo(word.startMs), vibrate once, stop on release or end, position ticks. Top build risk: word-timestamp ↔ audio-clock alignment — spike this first.
  • noteStore — load/save documents/note.json; empty result ⇒ no segment; errors ⇒ the approved "unavailable" bubble.
  • transcri/transcri.ts — the swappable facade; huggingFace.ts is the only implementation (free token in .env, word timestamps requested); a Google swap later touches this folder only.
  • segments.ts — pure types + helpers (create/insert/edit-text/word→time); the only Jest-tested file.

Data Model

// src/features/segments.ts — the whole persistent shape type Word = { text: string; startMs: number; endMs: number }; type Segment = | { id; kind: "typed"; text: string } | { id; kind: "voice"; text: string; audioUri: string; // documents/recordings/<id>.m4a durationMs: number; words: Word[] | null }; // null = transcribing or failed type Note = { segments: Segment[]; updatedAt: number }; // = note.json

No tables — one JSON document (learner decision). DESIGN.md's SQLite schema is the upgrade path, not this POC. Audio files live beside note.json; only paths are stored (DESIGN.md 3.3, kept).
