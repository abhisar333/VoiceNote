What this app is

VoiceNote is an Android Expo app for notes made of blocks: typed lines and voice recordings that keep their audio and play back from any word you long-press. The home page lists notes as square tiles (search, sort, rename, delete); opening one gives an editor with a red record button. What runs it:

  • UI: two screens — src/screens/HomeScreen.tsx (tiles) and src/screens/NoteScreen.tsx (editor), with blocks rendered by src/components/SegmentBubble.tsx.
  • State: App.tsx holds the notes list and every handler.
  • Storage: one JSON file documents/notes.json plus audio files in documents/recordings/, behind src/features/noteStore.ts.
  • External service: Groq Whisper transcribes recordings (src/features/transcription/).

One action, end to end

Typed blocks skip the middle: a line typed in the composer (NoteScreen.tsx) becomes a block on blur/record/leave, via addTypedSegment() in src/features/segments.ts.

Reference route (not walked interactively)

A suggested 2–3-stop path through the code — offered as a reference, not something completed in a session.

  1. The kernel entry point. App.tsx → search handleRecordPress. Tap record → startRecording; tap again → stopRecording appends the voice block, then runTranscription runs. This one function is where the PRD's steps 2–4 live.
  2. Transcription and word timings. src/features/transcription/groq.ts → search toWords. Groq's response (seconds) becomes the note's Word[] (milliseconds) — the exact data src/features/player.ts's startSeek() later seeks to when you long-press a word.
  3. Persistence. src/features/noteStore.ts → loadNotes / saveNotes. The whole app reads and writes through this one module — which is why swapping to SQLite later touches only this file (see devpost/production-notes.md).

A practice to reuse

Specify the observable result, edge cases included. This project's PRD stated the silent-take rule as something a tester can see: record silence → show "no audio recorded", add no block (devpost/prd.md, Transcription section). When Whisper actually returned a lone . for silence, the mismatch was obvious against that written result, and the fix could be stated just as precisely — "punctuation-only words are dropped" (git commit 1f0cb85, slice 5 of devpost/checklist.md; the filter is in groq.ts → toWords).

Why it transfers: a requirement phrased as an observable behavior gives whoever builds (human or agent) a check they can run and a mismatch they can't explain away — on any project, in any language.
